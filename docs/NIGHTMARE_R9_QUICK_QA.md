# NIGHTMARE R9 — prueba rápida (build de desarrollo)

La build `qa-output/NEXUS-BLOCKS-NIGHTMARE-QA-ONLY.sb3` es independiente de `NEXUS-BLOCKS-ENDLESS.sb3`. No utilizar la build QA como release: contiene atajos. Para regenerarla desde la raíz: `python tools/nightmare/build_qa_fixture.py`; la normal se genera con `python tools/build_sb3.py`. En la build normal no existen las variables ni bloques de los atajos 5, 6 y 7. `python -m unittest discover -s tools/nightmare -p 'test_*.py'` comprueba el aislamiento.

1. Descarga la build QA desde esta rama y ábrela en el editor Scratch 3 usando Archivo → Cargar desde tu ordenador. Se necesita Scratch 3 funcional, WebGL y teclado; para iPad usar teclado externo si el navegador/editor permite las entradas. Este proyecto no añade controles táctiles.
2. Pulsa la bandera verde; selecciona NIGHTMARE con **4** (pulsa 4 otra vez para alternar TRIALS/ENDLESS) y empieza con **Enter**. Espera a que termine la introducción. Para aislar un caso pulsa **R** y espera a que inicie de nuevo.
3. **Glitch: 5.** Solo funciona mientras juegas NIGHTMARE y no hay amenaza ni Jam activos. Observa CHARGE y ACTIVE y entra deliberadamente en los ataques: anota 3→2→1→0, destello, sonido, resultado, aviso de 2 filas y las dos fijaciones hasta el castigo. Repite con R y esquiva para comprobar +100 una vez. Las flechas mueven el núcleo; P pausa. Graba el resultado si puedes.
4. **Triple: 6.** Solo funciona en juego y sin amenaza activa. Aparece aviso de 3 filas y cuenta de 5 fijaciones; pulsa espacio para fijar piezas, observa que llegan tres filas con un hueco cada una, o limpia dos líneas por cada fila a cancelar antes de que venza el aviso. Evita top-out para comprobar todas las filas; repite con tablero alto para top-out.
5. **Burst: 7.** Programa el inicio 2,1 segundos después del tiempo de juego actual. Observa `BURST SOON`, luego `SPEED BURST`, la caída acelerada y su vuelta a la velocidad normal. Pausa con P durante Burst y comprueba que el tiempo de juego no avanza; reanuda. R permite reiniciar entre casos.
6. Anota dispositivo, navegador, versión del archivo, sonidos, capturas y si alguna colisión no coincide con lo que se ve. También prueba la build normal sin los atajos para comprobar la experiencia real y los calendarios. Las teclas de QA preparan eventos: no demuestran que su programación natural o balance estén correctos.
